# poster — автопублікація шортсів

Модуль бере готові шортси з `ready/<Гра>/*.mp4` (+ `*.json` від `generate_meta.py`),
розкладає їх по слотах і **після вашого підтвердження в Telegram** публікує через офіційні API:

| Платформа | API | Як публікується |
|---|---|---|
| YouTube Shorts | YouTube Data API v3 (OAuth) | публічно, «не для дітей», категорія «Ігри» |
| Instagram Reels | Instagram Graph API | акаунт «Автор», прив'язаний до сторінки FB |
| Facebook Reels | Graph API (`video_reels`) | окремою публікацією на сторінку |
| TikTok | Content Posting API (Direct Post) | до аудиту — приватно, після — `"public": true` |

Без платних сервісів і неофіційних завантажувачів. Відео завантажуються прямо з ПК.

---

## 1. Як це працює

```
ready/WoT/clip.mp4 + clip.json (status: ready_to_post)
        │  сканування щохвилини → у кінець черги (FIFO)
        ▼
за 1 год до слоту ─► Telegram: сам шортс відеоповідомленням + кнопки, другим повідомленням тексти TT/IG/FB
        │
   [🚀 Опублікувати] ──► у час слоту ──► YT, TT, IG, FB (кожна незалежно, 3 спроби)
        │                                   │
   немає підтвердження до слоту              ▼
        ▼                          posted/РРРР-ММ-ДД/clip.mp4 + clip.json (з id/посиланнями)
   слот порожній, шортс у кінець черги      │
   після 3 пропусків → skipped/              ▼
                                   звіт увечері + перегляди через 24 год
```

* Слоти — з `config.json` (типово 10:00, 13:00, 16:00, 19:00, 21:00, Europe/Kyiv; до 6 на день).
  Надлишок шортсів просто чекає в черзі наступних днів.
* Стан черги — у `data/poster.sqlite3`. Після перезапуску ПК усе продовжується з того ж місця:
  - підтверджений шортс, слот якого минув менш ніж `catchup_minutes` (120 хв) тому, публікується одразу;
  - якщо ПК був вимкнений довше — шортс повертається **на початок** черги без штрафу;
  - перервана посеред публікації (вимкнули світло) — дозавантажується лише на ті платформи, де ще не вийшла.
* Відео в Telegram більше 50 МБ (ліміт Bot API) → бот надсилає стиснуту 720p-копію (ffmpeg).
  **Публікується завжди оригінал.**

## 2. Встановлення (Windows 10/11)

1. **Python 3.11+** з [python.org](https://www.python.org/downloads/) — під час встановлення відмітьте *Add python.exe to PATH*.
2. **ffmpeg**: завантажте збірку (наприклад, «release essentials» з gyan.dev), розпакуйте в `C:\ffmpeg`
   і або додайте `C:\ffmpeg\bin` у PATH, або вкажіть у `config.json`:
   `"ffmpeg": "C:/ffmpeg/bin/ffmpeg.exe", "ffprobe": "C:/ffmpeg/bin/ffprobe.exe"`.
3. Скопіюйте папку `poster` на ПК (наприклад, `D:\Shorts\poster`) і запустіть **`setup.bat`** —
   він створить `.venv`, встановить залежності та скопіює `config.json` і `.env` з прикладів.
   (Вручну те саме: `python -m venv .venv`, `.venv\Scripts\pip install -r requirements.txt`,
   `copy config.example.json config.json`, `copy .env.example .env`.)

4. Відредагуйте `config.json` (шляхи до папок) та `.env` (ключі — див. розділ 4).

> Усі ключі й токени зберігаються лише в `.env`, `client_secret.json` і папці `tokens/`.
> Вони внесені в `.gitignore` — не комітьте і не пересилайте їх.

## 3. Налаштування `config.json`

| Параметр | Що означає |
|---|---|
| `slots` | Час публікацій, 1–6 значень `"HH:MM"` |
| `timezone` | Часовий пояс (`Europe/Kyiv`) |
| `notify_before_minutes` | За скільки хвилин до слоту надсилати шортс у Telegram (60) |
| `min_notify_lead_minutes` | Не надсилати, якщо до слоту лишилось менше (5 хв) |
| `publish_on_approve` | `false` — публікувати в час слоту; `true` — одразу після натискання кнопки |
| `catchup_minutes` | Скільки хвилин після слоту ще можна опублікувати підтверджений шортс після перезапуску ПК |
| `max_skips` | Після скількох пропусків переносити в `skipped/` (3) |
| `paths.ready/posted/skipped` | Робочі папки (абсолютні або відносно `config.json`) |
| `ready_status` | Яке значення `status` у json означає «готово» (`ready_to_post`) |
| `regenerate_command` | Команда для кнопки «Перегенерувати тексти». Підстановки: `{mp4}`, `{json}`, `{game}` |
| `regenerate_cwd` | Робоча папка для цієї команди |
| `platforms.*.enabled` | Увімкнути/вимкнути платформу повністю |
| `platforms.youtube.privacy` | `public` / `unlisted` / `private` |
| `platforms.tiktok.public` | `false` — приватно (SELF_ONLY) до аудиту, `true` — публічно |
| `retry.attempts`, `retry.pause_seconds` | Кількість спроб і пауза між ними (3 × 120 с) |
| `reports.daily_time` | Час щоденного підсумку (22:30) |
| `reports.stats_after_hours` | Через скільки годин збирати перегляди (24) |
| `reports.health_check_time` | Час щоденної перевірки токенів усіх платформ (09:00, до першого слоту) |
| `graph_api_version` | Версія Graph API Meta (`v25.0`; версії живуть ~2 роки — оновлюйте за потреби) |
| `dry_run` | `true` — увесь процес без реальних публікацій (для перевірки бота) |

### Формат json від `generate_meta.py`

Модуль читає гнучко, але очікує приблизно таке:

```json
{
  "status": "ready_to_post",
  "youtube":   { "title": "Назва", "description": "Опис", "tags": ["wot", "танки"], "hashtags": ["#wot", "#танки"] },
  "tiktok":    { "caption": "Текст для TikTok #wot" },
  "instagram": { "caption": "Текст для Reels #wot" },
  "facebook":  { "caption": "необов'язково — інакше береться текст Instagram" }
}
```

`tiktok` / `instagram` можуть бути й простими рядками. Якщо в тексті немає хештегів — додаються `hashtags` з YouTube.
Після публікації в json дописується блок `posting` (id, посилання, час, статус кожної платформи) і `status: "posted"`;
через 24 год — `posting.views_24h`.

## 4. Отримання ключів

### 4.1 Telegram

1. У Telegram відкрийте **@BotFather** → `/newbot` → задайте ім'я → отримаєте токен `123456:ABC...`.
   Запишіть у `.env`: `TELEGRAM_BOT_TOKEN=...`
2. Дізнайтесь свій chat_id: напишіть **@userinfobot** — він покаже `Id`. Запишіть `TELEGRAM_CHAT_ID=...`
3. Відкрийте свого бота і натисніть **Start** (інакше бот не зможе вам писати).

Бот реагує **лише** на ваш chat_id; повідомлення від інших ігноруються (і записуються в log.txt).

### 4.2 YouTube

1. [console.cloud.google.com](https://console.cloud.google.com/) → створіть проєкт (наприклад, `shorts-poster`).
2. **APIs & Services → Library** → знайдіть **YouTube Data API v3** → **Enable**.
3. **OAuth consent screen** (Google Auth Platform): тип **External**, заповніть назву і пошту,
   у **Audience / Test users** додайте свій Google-акаунт.
   ⚠️ Потім натисніть **Publish app → In production**. Поки застосунок у режимі *Testing*,
   refresh-токен живе лише **7 днів**. Для власного використання верифікація не потрібна —
   під час входу просто натисніть «Додатково → Перейти до (небезпечно)».
4. **Credentials → Create credentials → OAuth client ID → Desktop app** → завантажте JSON,
   перейменуйте на `client_secret.json` і покладіть поруч із `poster.py`.
5. Виконайте `.venv\Scripts\python poster.py auth youtube` — відкриється браузер, увійдіть
   у Google-акаунт **каналу** @mr_antibiotik (якщо каналів кілька — виберіть потрібний) і дозвольте доступ.
   Токен збережеться в `tokens/youtube_token.json`.

**Квота:** 10 000 одиниць/день; одне завантаження ≈ 1 600 од. → до 6 шортсів на день вистачає.

**Важливо про аудит:** відео, завантажені через API з **неперевірених** проєктів (створених після 28.07.2020),
YouTube автоматично робить **приватними**. Щоб публікувати публічно, подайте безкоштовну форму
*YouTube API Services — Audit and Quota Extension Form* (у документації YouTube Data API).
Поки аудит не пройдено, бот покаже примітку «YouTube встановив статус private» — відкрийте відео вручну в Studio.

### 4.3 Meta (Instagram Reels + Facebook Reels)

Підготовка:
* Instagram має бути **професійним акаунтом (Автор)** і **прив'язаним до сторінки Facebook**
  (Instagram → Налаштування → Центр облікових записів / або в налаштуваннях сторінки FB → Пов'язані акаунти).

Застосунок:
1. [developers.facebook.com](https://developers.facebook.com/) → **My Apps → Create App** → тип **Business**
   (або сценарії «Manage everything on your Page» + «Instagram API with Facebook Login»).
2. Скопіюйте **App ID** і **App Secret** (Settings → Basic) у `.env`: `META_APP_ID`, `META_APP_SECRET`.
3. Застосунок може лишатися в режимі **Development** — для акаунтів, де ви адміністратор застосунку,
   публікація працює без App Review.

Токен:
1. Відкрийте [Graph API Explorer](https://developers.facebook.com/tools/explorer/), виберіть свій застосунок,
   **User Token**, додайте дозволи:
   `pages_show_list, pages_read_engagement, pages_manage_posts, read_insights, business_management,
   instagram_basic, instagram_content_publish, instagram_manage_insights`
2. **Generate Access Token** → увійдіть, виберіть сторінку і Instagram-акаунт → скопіюйте токен.
3. Виконайте `.venv\Scripts\python poster.py auth meta` і вставте токен.
   Скрипт обміняє його на довготривалий і запише в `.env` **безстроковий токен сторінки**
   (`META_PAGE_TOKEN`), `FB_PAGE_ID` та `IG_USER_ID`.

Токен сторінки стає недійсним, лише якщо ви зміните пароль Facebook, знімете права застосунку
або вийдете з адмінів сторінки — тоді бот напише «потрібна повторна авторизація», і крок 1–3 треба повторити.

### 4.4 TikTok

1. [developers.tiktok.com](https://developers.tiktok.com/) → увійдіть → **Manage apps → Connect an app**.
2. Заповніть опис застосунку (іконка, назва, категорія, посилання на Terms/Privacy — можна сторінку каналу).
3. **Add products**: **Login Kit** і **Content Posting API** — в останньому увімкніть **Direct Post**.
4. **Scopes**: `user.info.basic`, `video.publish`, `video.list`.
5. У Login Kit вкажіть платформу **Desktop** і Redirect URI `http://localhost:8765/callback/`
   (те саме значення — в `config.json → platforms.tiktok.redirect_uri`).
   Якщо портал вимагає https-адресу — вкажіть будь-яку свою; тоді після входу скопіюйте з браузера
   повну адресу, на яку вас перенаправило, і вставте в консоль.
6. Скопіюйте **Client key** і **Client secret** у `.env`: `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`.
7. Поки застосунок не пройшов аудит — у розділі **Sandbox** додайте свій TikTok-акаунт як *target user*.
8. Виконайте `.venv\Scripts\python poster.py auth tiktok`, увійдіть і дозвольте доступ.
   Токен (`tokens/tiktok_token.json`) оновлюється автоматично; refresh-токен дійсний 365 днів.

**Приватність:** неаудитовані застосунки можуть публікувати **лише приватно** (`SELF_ONLY`) —
тому типово `"public": false`. Відкривайте пост вручну в застосунку TikTok.
Після проходження аудиту (Submit for review у порталі) поставте `"public": true`.
Перегляди для приватних постів API не віддає — у звіті буде «н/д».

## 6. Тест (критерій готовності)

1. **Сухий прогін:** у `config.json` поставте `"dry_run": true`, запустіть `run_poster.bat`,
   покладіть шортс у `ready/WoT/`, у боті надішліть `/testslot 10`.
   Прийде відео з кнопками → натисніть **Опублікувати** → о вказаній хвилині підпис зміниться
   на «✅ Опубліковано», файли переїдуть у `posted/<дата>/`. Звіт — командою `/report`.
2. **Справжній тест:** `"dry_run": false`, перезапустіть, `/testslot 10` → підтвердіть →
   перевірте пост на YT / IG / FB і приватний пост у TikTok, json у `posted/`, звіт `/report`.
3. **Перезапуск:** коли шортс чекає підтвердження, перезавантажте ПК — після входу бот напише
   «🟢 poster запущено», а слот і кнопки продовжать працювати.

Тести без мережі (логіка черги, бот, модулі платформ на підставних відповідях API):
`.venv\Scripts\python -m unittest discover -v`

## 7. Автозапуск через Планувальник завдань

```powershell
powershell -ExecutionPolicy Bypass -File install_task.ps1
```

Створює завдання **ShortsPoster**: запуск при вході в Windows (через 1 хв), без вікна,
без обмеження часу, автоперезапуск при збої, лише один екземпляр.
Видалити: `uninstall_task.ps1`.

Обов'язково: **Параметри → Система → Живлення → Сон: Ніколи**, інакше ПК засне і пропустить слоти.
Для запуску без входу в Windows налаштуйте автоматичний вхід або змініть у Планувальнику
«Виконувати незалежно від входу користувача».

## 8. Користування ботом

Сповіщення за годину до слоту:

```
🎬 Назва YouTube
#wot #танки
🕐 Слот: 13:00 | Платформи: YT ✅ TT ✅ IG ✅ FB ✅

⏳ Очікує підтвердження до 13:00
[🚀 Опублікувати]
[🔄 Перегенерувати тексти]
[✏️ Ввести назву вручну]
Вимкнути платформу:  [YT ✅] [TT ✅] [IG ✅] [FB ✅]
```

* **Опублікувати** — підтвердження; публікація відбудеться в час слоту (кнопка зміниться на «Скасувати підтвердження»).
* **Перегенерувати тексти** — запускає `regenerate_command`, оновлює підпис і повідомлення з текстами.
* **Ввести назву вручну** — бот попросить надіслати нову назву для YouTube (до 100 символів).
* **YT/TT/IG/FB** — вимкнути/увімкнути платформу саме для цього шортса.
* Після слоту підпис оновлюється: **✅ Опубліковано** з посиланнями, **⏭ Пропущено**, **✏️ Змінено**.

Команди: `/queue` — черга, `/status` — найближчі слоти, `/report` — підсумок дня,
`/retry N` — повторити невдалі платформи, `/testslot 10` — позаплановий слот, `/cancel`.

Службові повідомлення:
* ⚠️ платформа не спрацювала після 3 спроб (з причиною) — інші платформи публікуються незалежно;
* 🔑 «Потрібна повторна авторизація: …» — із командою, яку треба виконати на ПК.
  Токени перевіряються **щодня о 09:00 і при запуску**, тож про проблему ви дізнаєтесь до слоту,
  а не під час публікації; за 14 днів до кінця дії refresh-токена TikTok прийде попередження.
  Поточний стан доступів — у `/status`;
* 🗑 шортс пропущено 3 рази → `skipped/`;
* 📊 щоденний підсумок о 22:30; 👁 перегляди через 24 год після публікації.

## 10. Типові проблеми

| Симптом | Що робити |
|---|---|
| Бот мовчить | `python poster.py check`; чи натиснули Start у боті; чи правильний `TELEGRAM_CHAT_ID`; дивіться `log.txt` |
| «poster уже запущено» | Завдання вже працює у фоні — це нормально. Зупинити: Планувальник → ShortsPoster → Завершити |
| YouTube: відео приватне | Проєкт не пройшов аудит API (розділ 4.2) |
| YouTube: `quotaExceeded` | Денна квота вичерпана; скидається опівночі за тихоокеанським часом |
| YouTube: авторизація кожні 7 днів | OAuth consent screen у режимі Testing → переведіть у Production |
| Instagram: помилка 2207026 / формат | Відео має бути MP4 H.264/AAC, 9:16, 3–90 с (для Reels до 15 хв — залежить від акаунта) |
| TikTok: `unaudited_client_can_only_post_to_private_accounts` | Тримайте `"public": false` до проходження аудиту |
| Шортс не потрапляє в чергу | У json має бути `"status": "ready_to_post"`, mp4 і json — з однаковою назвою в `ready/<Гра>/` |
