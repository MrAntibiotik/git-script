# Multistream — OBS-плагін для стріму на кілька платформ

Стрім одночасно на Twitch, YouTube, Kick, TikTok, Facebook або будь-який RTMP-сервер.
Кожна платформа отримує **окремий потік зі своїм бітрейтом і роздільністю**.
**Бітрейт можна міняти просто під час стріму** — без перезапуску трансляції.

## Встановлення

1. OBS → **Інструменти → Скрипти**. Для Python-скриптів у вкладці **Налаштування Python** вкажіть шлях до Python 3
   (на Windows — Python 3.11/3.12 x64 з python.org).
2. На вкладці **Скрипти** натисніть **+** і виберіть `multistream.py`.

## Налаштування

Для кожного з 4 потоків:

| Поле | Що вказати |
|---|---|
| Галочка «Потік #N» | Увімкнути цей потік |
| Платформа | Twitch / YouTube / Kick / TikTok / Facebook / Власний RTMP |
| Сервер | Для Twitch, YouTube, Facebook підставляється сам. Для Kick і TikTok скопіюйте з панелі стрімера |
| Ключ потоку | Ключ із панелі платформи |
| Енкодер | x264 (процесор), відеокарта (NVENC / AMF / QuickSync) або **«Як основний потік OBS»** |
| Бітрейт відео | Можна міняти під час стріму |
| Роздільність | Наприклад, 1080p на YouTube і 720p на Twitch |
| Кадри/с | «Як в OBS» або «Половина» (60 → 30), щоб зекономити ресурси на другорядній платформі |
| Старт разом з «Почати трансляцію» | Потік стартує/зупиняється разом з основною кнопкою OBS |

Кнопки **▶ Запустити всі / ■ Зупинити всі**, а також **▶ Старт / ■ Стоп** для кожного потоку.

### Зміна бітрейту під час стріму

Під час трансляції пересуньте повзунок «Бітрейт відео» потрібної платформи.
Через ~1 секунду новий бітрейт застосовується до потоку, а в лозі скрипта з'являється рядок
`Twitch: бітрейт змінено 6000 -> 4500 кбіт/с`.

Зміну на льоту підтримують **x264** і **NVENC** (OBS 30+). Інші енкодери можуть
застосувати новий бітрейт лише після перезапуску потоку.

### YouTube 20 000, Twitch 6000 одночасно

Головна ідея плагіна: кожна платформа має свій потік, тому бітрейти незалежні.
Типове налаштування:

| Платформа | Бітрейт | Роздільність |
|---|---|---|
| YouTube | 20 000 кбіт/с (за замовчуванням) | 1440p або як в OBS |
| Twitch | 6000 кбіт/с | 1080p або 936p/720p |

Вгорі є поле **«Ліміт бітрейту Twitch»** (за замовчуванням 6000). Twitch-потік ніколи не
перевищить це значення, навіть якщо повзунок випадково виставлено вище, а в лозі буде попередження.
Якщо ваш канал має вищий ліміт (наприклад, 8000), просто змініть це поле.
Повзунок бітрейту йде до 51 000 кбіт/с (максимум YouTube для 4K).

### Монітор 16:10

Плагін зберігає пропорції, тому картинка ніколи не розтягується. Але при полотні 16:10
(наприклад, 2304×1440 або 2560×1600) глядачі з екранами 16:9 бачитимуть чорні смуги з боків.

Краще зробити полотно 16:9, а монітор 16:10 вписати в нього:
1. **Налаштування → Відео:** базова роздільність **2560×1440**, вихідна теж **2560×1440**.
2. **Захоплення екрана:** або обрізати 160 px (80 зверху і 80 знизу) через Alt+перетягування чи
   «Фільтри → Обрізати/Доповнити», або «Трансформувати → Вписати в екран» (тоді смуги будуть з боків, але
   тільки там, де ви самі вирішите).
3. У плагіні: YouTube «Як у налаштуваннях OBS» (2560×1440, 20 000 кбіт/с), Twitch 1080p (1920×1080, 6000).

### Рекомендовані налаштування (приклад: RTX 5070, Ryzen 5 7500F)

OBS → Налаштування → Відео: базова й вихідна роздільність **2560×1440**, **60** кадрів/с.

| Потік | Платформа | Енкодер | Бітрейт | Роздільність | Кадри/с |
|---|---|---|---|---|---|
| #1 | Twitch | NVIDIA NVENC H.264 | 6000 | 1080p | Як в OBS |
| #2 | YouTube | NVIDIA NVENC AV1 (або H.264) | 20 000 | Як в OBS (1440p) | Як в OBS |

Обидва потоки кодуються на окремому чипі NVENC у відеокарті, а не на процесорі.
**AV1** дає кращу якість на YouTube при тому самому бітрейті. Twitch, Kick, TikTok і Facebook
приймають лише H.264, тому плагін не дасть запустити на них AV1/HEVC і напише про це в лозі.

### Інші можливості

- **«Як основний потік OBS»:** потік бере вже готове відео основної трансляції, тому додаткового навантаження немає.
  Бітрейт і роздільність тоді такі самі, як в основному потоці, повзунок на нього не діє.
  Основну трансляцію треба запустити першою.
- **Затримка трансляції:** якщо в OBS увімкнено «Розширені → Затримка потоку», вона застосовується й до всіх потоків плагіна.
- **WHIP:** якщо адреса сервера містить `whip`, потік іде через WebRTC (WHIP), а ключ передається як bearer-токен.
- **Лог:** у лозі скрипта видно «в ефірі», «перепідключення», «перепідключено» і причину зупинки
  (наприклад, «сервер відхилив потік (перевірте ключ)»).
- Зменшення роздільності йде на відеокарті (бікубічне), як в Aitum і obs-multi-rtmp.
- Зміна профілю OBS зупиняє всі потоки плагіна, щоб вони не продовжували йти зі старими налаштуваннями.

Ці можливості зроблені за прикладом [obs-multi-rtmp](https://github.com/sorayuki/obs-multi-rtmp) і
[Aitum Multistream](https://github.com/Aitum/obs-aitum-multistream): ідеї звідти перенесено,
але код написано заново на Python.

## Поради

- Twitch: зазвичай не більше 6000 кбіт/с (для деяких каналів 8000). Ключовий кадр уже стоїть 2 с, як вимагає Twitch.
- Для 20 000 кбіт/с на YouTube базова роздільність OBS має бути 1440p (або 4K). Для 1080p YouTube рекомендує до ~12 000.
- Кожен потік кодується окремо. 3–4 потоки на x264 сильно навантажують процесор, тому краще брати енкодер відеокарти.
- Сумарна швидкість інтернету має бути більшою за суму бітрейтів усіх потоків.
- Основний вихід OBS («Почати трансляцію») теж стрімить на свою платформу, тому не дублюйте її в плагіні.
  Або зробіть основним будь-який сервіс, а всі платформи ведіть через плагін.
